一句话：为了让实验能落地，先把执行面查清 —— AutoDL 实例（4090 24G / 50GB 数据盘 / 200GB 文件存储） 与局域网 GTX 1080 Ti 工作机（11G 显存 / 15GiB 内存 / 1.5T 数据盘）逐项实测 → 两个判负（Strata 在两台机器上都跑不起来；账户资金不够长跑），一个正收益（1080 Ti 以 5,075 tok/s 承接探针， 不必充值）→ 顺手把飞书写入从「读全文再整篇覆盖」改成「只发增量」。

0. 摘要

本线要回答的是执行面问题，不是模型问题：现有 AutoDL 实例能干什么、局域网那台 GTX 1080 Ti 能不能顶上、 Strata（Qwen3.8-Flash-Next 125B MoE 的本地推理方案）到底卡在哪、以及长跑日志怎么存才不丢。

结论分三块。判负：Strata 在 AutoDL 那台卡在磁盘（最大可写目录 50GB，官方要求约 80GB，且该机不支持扩容）， 在局域网那台卡在内存（最小档 Gyro-S 需 27.6 GB 显存+内存合计，本机 11 GiB + 15 GiB ≈ 26 GiB）； 正收益：局域网 1080 Ti 实测 RWKV-7 162 M 前向 5,075 tok/s，10k prompt 状态抽取约 17 分钟， 把「先充值再跑探针」这个前置依赖直接消掉；工程：飞书云文档从整篇 overwrite 改成 append 增量写入， 配 Base 时间线做双视图，并沉淀出一条规则——判成功用 ok == true 而不是 code == 0。

1. 问题与假设

决策问题（每条都对应「要不要花钱」）：

  1. 要不要继续给 AutoDL 充值、租 4090？——需要知道现有实例状态、账户资金、以及 AutoDL 到底哪些能力有 API。
  2. 有没有零租金的替代执行面？——局域网那台 GTX 1080 Ti 到底能跑什么、不能跑什么。
  3. Strata（用户提出的”本地跑 Qwen3.8”方案）值不值得投入时间？——需要给出「跑不动」的硬门槛，而不是”试试看”。
  4. 实验日志写到哪里、怎么写才不会互相覆盖？——飞书云文档 + 多维表格时间线。

预注册判据：

问题 判据 通过条件
1080 Ti 能否跑探针 S1–S4 只需纯 PyTorch 前向 前向吞吐可测且状态可取出
Strata 能否在 1080 Ti 跑 权重 GB ≤ RAM + VRAM 才算 fits（fit_label.py） 最小档 27.6 GB ≤ 26 GiB
增量写入是否更好 不读全文、不覆盖云端手工改动 只发本条增量且 rev 递增

为什么怀疑已有做法：旧同步脚本 sync.sh 的默认值是 TOKEN="${2:-${DOC_TOKEN:-}}"， 而项目 targets.env 永远有 DOC_TOKEN —— 意味着「新建文档」分支实际走不到，任何”新建”都会覆盖主文档。 这条不是猜的，是本轮真实发生并靠历史版本回滚恢复的事故（见 §5）。

3.3 反直觉 / 负结果

  1. Strata 判负的瓶颈不是显卡。直觉上 11 GB 显存跑不动 125B MoE 是”显卡不够”， 实测卡点是 15 GiB 系统内存：最小档要 27.6 GB（显存+内存合计），本机合计 ≈26 GiB； 官方 --check 直接判 This PC cannot run Strata yet（exit 1），且 any_fits 不把 mem_total 类的 Gyro 计入。 low-RAM 兜底也不够：ram-6 + (vram-5-MTP) ≈ 14.5 < Coder arena 23.4。
  2. 磁盘不是所有机器的瓶颈。AutoDL 那台是磁盘（50 GB < 80 GB 需求，且不支持扩容）； 1080 Ti 那台是内存（1.5 T 余量对 58–84 GB 下载完全够）。同一份”能不能跑”的结论，两台机器的死因相反。
  3. 「4090-48G 约 ¥3.03/h」这条成本口径没能用上：账户资金 < ¥20，连 8 小时都跑不了； 忘关一天 ≈ ¥73 的说法在本线只作为风险提示，没有真实账单支撑。
  4. 飞书「授权成功 ≠ 权限齐全」：auth login 返回 ok 的同时可能带 warning.type = missing_scope； 本轮实测仍是 155 个 scope，im:message.send_as_user / wiki:node:update / contact:user.base:readonly / base:workflow:delete 均缺失，发消息只能继续走 Open API 应急通道。
  5. 公开 API 不覆盖普通实例：instance/pro/list 返回 result_total=0 不是”没有实例”， 而是「现有实例是普通容器实例，不在 Pro API 管辖内」——差点被误读为实例已释放。
  6. 位置/端口随时会变：实例停止后 SSH 端口即失效（kex_exchange_identification），开机换新端口； 切有卡模式也会换端口。这条不能当作故障，但会反复消耗排查时间。

4. 结论与判定

  • 判定：部分完成。执行面事实已查清并留下可复核证据；两个方向判负（Strata、AutoDL 长跑）、 一个替代执行面确认可用（1080 Ti + 纯 PyTorch）、工具链改造完成。
  • 可写（支持的结论）：
    1. Strata 在 1080 Ti 工作机上跑不起来，硬约束是 15 GiB 内存：最小档 Gyro-S 需 27.6 GB（显存+内存合计）， 本机合计 ≈26 GiB；另有驱动 525 < 575.51、Pascal 实验路径、Ubuntu 18.04 三条次要门槛。
    2. Strata 在 AutoDL 那台 4090 上跑不起来，硬约束是磁盘：官方要求约 80 GB 单可写目录， 该机最大可写目录 50 GB，且用户确认不支持扩容。
    3. 1080 Ti 足以承接 RWKV-7 探针：162.2 M 前向 5,075 tok/s，10k prompt × 512 token ≈ 17 分钟， 状态 1.9 GB；前提是走纯 PyTorch路径（sm_61 用不了 Triton/FLA），且 CPU 密集型部分会被 19 天的长任务挤。
    4. 增量写入解决了”每写一条都要读全文”的问题，且默认值不再是破坏性的（feishu-sync 不传 token 走 create）。
  • 不可写（诚实边界）：
    1. 不能说”局域网机可以替代 AutoDL”：9B fp16 ≈18 G > 11 G，E1 的 LLM-judge 与 Strata 都不行； 它只顶掉了「探针」这一段。
    2. 不能说”Strata 升级后就能跑”：升到 ≥32 GB 内存 + 驱动 580 只够跑最小档， Pascal 是官方明说的实验路径（很多开关”未在 CC 6.1 实测”），且引擎包 glibc 下限在 18.04 上未验证。
    3. 不能说”飞书权限已配齐”：权限层仍缺「列出/移除协作者」4 组 scope，消息链路仍靠应急通道。
    4. 不能说”17 min/10k prompt 是端到端探针成本”：这是前向吞吐换算值，不含数据加载、落盘与 CPU 争抢的实测。
  • 对后续决策的含义：探针线继续（零租金）；AutoDL 只在需要 9B 及以上模型时开机，且开机前必须先解决账户资金； Strata 计划停在这里，不再尝试下载。

5. 踩坑与修正

现象 根因 解法
source /etc/network_turbo 后 GitHub / HF 仍 HTTP 000 该实例上加速代理已不生效（与 COLD-START.md §4 记载不符） 可行线路只剩 hf-mirror；文档结论标记为时效性失效
同一文件不同 Range 速度差 100 倍（31 KB/s vs 3.9 MB/s） 限速是按字节段而非按文件 curl -C - 分段续传，越过慢段后回升（实测 8.6 MB/s）
文件字节数与 HF API 的 size 对不上（差 733 KB） API 元数据会过期 校验一律以实际 Content-Length 为准
npm 报 EPERM ... root-owned files 误导：真因是沙箱不允许写工作区外，~/.npm 属主正常 先跑 touch ~/.dsh-write-test 验证沙箱，不要 sudo chown
lark-cli 报 not configured（配置齐全） workspace 由 HERMES_HOME 决定，未设时落到 local 封装 wrapper 固定 HERMES_HOME；单用 --profile 无效
keychain not initialized 沙箱挡住 macOS 钥匙串，不是凭证过期 放宽文件策略即可；报错先怀疑策略，再怀疑凭证
str_replace 改了但回读没变（$? 仍 0） 按文本 run 匹配，跨格式边界会失败；degrade_code=1013 时退出码仍是 0 判成功读 result/data 字段；格式问题走 block_replace
sync.sh <file> 未传第二参数 → 覆盖了主文档 旧版默认值 TOKEN="${2:-${DOC_TOKEN:-}}"，targets.env 永远有 DOC_TOKEN docs +history-list 取版本号 → history-revert 恢复；全局版改为默认 create
脚本报 TITLE?: unbound variable，但写入已经发生 bash 把 $VAR 紧跟的全角字符首字节并入变量名 一律写 ${VAR}；写操作后不要放可能失败的展开（本次因此多出一条重复 Base 记录，已删）
base +record-list 查不到刚写的记录 --page-size N 是从表头开始的第一页；--format json 下记录在 data 数组本身 放大 page-size 或翻页；按 data['items'] 解析会得 0 条
无卡模式装环境时 4B 模型静默 OOM cgroup 仍是 2 GB / 0.5 核 装环境用无卡模式，跑模型前切有卡
web_fetch 全部失败（non-public IP） 本机 DNS 把域名解析到 198.18.0.0/15 改用 bash 的 curl 做事实核查
远端长任务挂住 ssh 会话被前台进程占住 setsid nohup … & 起任务 + 另开会话轮询日志

6. 未做 / 下一步

  1. 账户资金：需要先充值（当前 < ¥20，不足 4090 跑 8 小时），这是 AutoDL 侧最硬的约束；充值前不开机。
