一句话：把权重按「激活概率 × 能量」重排后逐步清空，在 dense 模型上静态只买到 2–3% 的免费稀疏；真正免费的是逐 token 条件性（0.5B 20–30% → 4B/7B 约 40%），但精确选中「这个 token 需要哪些神经元」必须先算完全部 gate/up——选择的成本等于省下的成本；合并、组级、路由三条替代路线逐一判负，于是这个假设在 0.5B/1.5B/4B/7B 上一致判死。

0. 摘要

这条线要回答的是「压缩/条件计算能不能让模型住进更小的身体，或者把每次推断的焦耳降下来」，而不是「能不能刷一个更高的稀疏度」。做法是先做文献审计（12 篇 curl 核原文）确认哪些格子已被占，再把用户设想拆成 5 个自由度，用 R0–R13 系列预注册实验逐格扫「便宜且可能翻盘」的组合。结论是四句话：重排本身无损（R0），静态剪枝免费空间只有 2–3%（R1/R2），动态 oracle 的 20–40% 无法兑现为算力（R7/R13），结构性替代（合并 R5/R6、组级 R8）的近似误差都超过它省下的算力。判定判负——被判死的是「动态门控可兑现」这个假设，不是「稀疏性存在」这个事实。

1. 问题与假设

用户设想：把 LLM 权重按「激活的概率 × 能量」重排序，逐步清空低激活/低连接权重，结合 Goodfire《Neurons as an Interpretable Basis》。

先验审计的关键对照。Goodfire 的「消融 92.2% 弱激活、loss 只 +2.9%」依赖三个前提，本轮逐条检验它们能否迁移：

前提 论文事实（原文核对） 本轮的检验
动态逐 token Qwen3.6-35B-A3B（MoE）每 token 只留 top-320 / 4096 routed 神经元，权重未改 R3/R7/R13：动态免费空间真实存在，但选择成本无法摊掉
MoE 冗余 35B-A3B 只路由 8 个专家，冗余远高于 dense R5/R6：dense 神经元激活轮廓近正交，没有可合并的重复单元
训练恢复 91M SFT + 9M RL 才修回推理退化 R12：200 步（≈0.1M token）只能买回 ~70% 伤害

先验审计还给出两个必须正面的反例：LILA 的负结果（校准版 act-based 在 LLaMA-2-7B 上未优于免校准的 Abs/Split）、DAWS 自报的稳定性风险（token 级激活掩码跨样本 IoU 仅 0.20–0.35，而权重掩码 0.80–0.90 ⇒ 动态统计量压成静态决策会崩）。所以本轮的第一件事不是找更好的分数，而是先证伪「静态排序本身成立」。

预注册的判死条件：计划 §5 的 M1 定下「同稀疏度增益 <1pt 且 paired bootstrap CI 覆盖 0 ⇒ 判负」，M2 定下「recovery 后答案差 >3pt ⇒ 该压缩率不可用」；本轮逐路线追加的规则是「合并劣于同预算剪枝 ⇒ 判负」「粒度惩罚大于理论省算力 ⇒ 判负」（R7/R8 的逐条判读见 §4）。允许的结论形态是「压缩率—退化曲线 + 判负」，不是「必须找到能用的压缩率」。计划里原本排在最前面的 M-1（零剪枝的跨域稳定性预检）后来被降级未跑——因为静态能剪多少本身只有 2%，见 §6。

记账口径：以逆熵为食。 这条线沿用 11-10 代谢审计定的单位——1 单位食物 = 真实任务上可复现的 1pt 惊讶下降，并派生四条判据：

判据 含义 本线的对应
真食物 真实任务、可复现、成本低 RRF 检索（recall@10 0.967→1.0，但已吃尽）
伪食物（淀粉） 只在合成/代理指标上涨，不能降低未来惊讶 小规模树（器官尚未需要）
负食物 上表涨、真实任务跌，或纯自洽迭代 多步共鸣/全局 meta concat
残渣 曾经真食物但已饱和 RRF 的边际

剪枝在这个账本里不是食物，而是降低基础代谢率：它不增加「惊讶下降」，只减少「每次惊讶所需的焦耳」。于是单位从 pt / task 换成 pt / joule，判定也从「端到端答案」变成「端到端答案 且 模型能住进更小的身体」。这条口径直接改变了本轮的成功标准：静态免费 2–3% 在 pt/task 口径下约等于 0，在 pt/joule 口径下也只把参数量削掉 2–3%，身体尺寸几乎不变。另一个推论是「删除一个不产出的器官与长出一个新器官同为净收益」——因为维持成本下降了；但也因此，空转不等于可删：Goodfire 的 Q3（gate<0 ∧ up<0 双负）激活占全模型 ~1/3 激活量、只占 top-100 归因细胞的 1–8%，剪掉却毁推理（GSM8K 回答 token 1550→176，陷入循环自检）——那是「空转耗能却不捕食」的代谢病理，不能按「低激活 ⇒ 可删」处理。

为什么怀疑已有做法：按 PPL/KL 判定压缩是否成功已经被证伪过多次——INT6 困惑度改善但只有 51.3% 活跃 SAE 特征存活；GPT-2 剪 30% 神经元使 IOI 电路反转（17.7% acc），而困惑度排序反而更轻；几何存活不预测因果重要性。因此 §3 的判决必须带着这个边界读：本轮所有轮次仍以 held-out PPL 为主指标（见 §4 不可写第 4 条）。

2. 实验设置

2.1 环境

  • 0.5B / 1.5B：局域网 GTX 1080 Ti 11G（4 核，env ai = torch 2.5.1+cu121 / transformers 4.48.3），零租金。
  • 4B / 7B：AutoDL vGPU-48GB（¥3.03/h），切有卡后实例代号从 westb 变为 westc，域名与端口同步变更。
  • 总成本：报告记约 ¥1.6（AutoDL 约 15 min GPU + 若干小时无卡下载）；PROGRESS 同日只记「GPU 约 15 min ≈ ¥0.8」，两处口径不一致，以报告为准并保留疑点。

2.2 模型与数据

模型 结构 实验
Qwen2.5-0.5B dense，24 层，inter 4864，fp16 R0–R12 主体
Qwen2.5-1.5B dense，28 层，inter 8960 R7/R8 复现
Qwen3-4B-Base dense，36 层，inter 9728 R2/R3/R7/R8/R9/R13
Qwen2.5-7B dense，28 层，inter 18944 R2/R3/R8/R9/R12

校准集为 wikitext-103 train（8–32 段 × 512 token），评测集为 held-out validation（6–16 段 × 512 token）；数据里还准备了 TinyStories 作第二域，但本报告全部数字来自 wikitext。剪枝实现为前向 pre-hook 将神经元激活置零（可逆、不改权重）；恢复实验物理置零后再微调、且评估前重新归零（微调可能把被剪权重长回来）。

2.3 方法

任何「压缩/条件计算」方案由 5 个自由度构成，本轮把「便宜且可能翻盘」的格子全部扫掉：

① 单位：单个权重 / 单个神经元 / 神经元组 / 神经簇 / 注意力头
② 选择量：幅度 / 能量 / 频率 / 连接度 / 尾部风险
③ 时机：静态（一次决定）/ 半静态（按层/域）/ 动态（逐 token）
④ 恢复：无 / 分钟级微调 / 全量 SFT+RL
⑤ 兑现：非结构化稀疏 / 半结构化 2:4 / 结构化整块 / 动态 gather

指标统一为困惑度相对变化 ΔPPL=PPLpruned/PPLbase−1\Delta PPL = PPL_{pruned}/PPL_{base}-1；「免费」定义为 ΔPPL ≤1%。行为检查（生成长度、循环）在协议里是为 Q3 类损伤定义的，但最终报告只给出 PPL 数字，本模型上的行为结果没有记录（见 §4 不可写第 1 条）。此外用「召回率（vs oracle top-k 集合）」判断路由器是否有预测能力，但明确不把它当质量指标（见 §5）。

一句话机制：激活的稀疏性是逐 token 的条件性质，不是可静态化的资源；要精确选中「这个 token 需要哪些神经元」，就必须先算完全部 gate/up。唯一剩下的路径是「路由器与专家联合训练」（MoE 式），那已是改架构而非剪枝。

3.2 对照与消融

R0 重排无损：全层神经元同步置换（gate/up 行 + down 列）后 PPL 22.2006→22.2252（+1.1e-3，fp16 噪声级）。这一步排除了实现误差：后续任何掉点只能归因于「删除」。

0.98 +0.87% +0.25% +0.63%
0.95 +4.91% +3.08% +2.32%
0.90 +13.57% +6.41% +5.79%
0.80 +38.23% +17.09% +18.98%

这就是「免费 20–30% → 40%」的来源，也是整条线唯一让人兴奋的数字——但它需要真实 |a|，即先算完全部激活。同一 keep 下 mean ablation（Goodfire 的做法）不但没有优势，在 0.5B keep 90% 时反而更差（mean +11.8% vs 置零 +0.07%），所以 Goodfire 的 mean 优势不能迁移。

R4 把动态统计量压成静态排序（keep 97%）：E[|a|·1∈topk] +2.40%、P(j∈topk) +12.81%、秩平均 +2.23%，energy 基线 +2.18%；到 keep 90% 分别为 +13.46% / +36.62% / +14.67% / +13.57%。所有静态化尝试都退化到 energy 基线，纯频率更差——10× 的差距不是「排序量选错」，而是条件性本身无法被任何边缘统计量表示。

R5/R6 神经簇合并：

R5 朴素 k-means + 代表 + down 列求和 PPL 21.8→1638（+8836%）

R6 逐级与静态剪枝对照：合并 1% +2.98% vs 剪枝 +0.36%（8.3×）、3% +12.12% vs +2.18%（5.6×）、5% +19.82% vs +4.91%（4.0×）、10% +34.26% vs +13.57%（2.5×）——合并严格劣于剪枝。根因实测：每层最近邻余弦 mean 0.299–0.475、p90 0.42–0.67；cos>0.9 的神经元对全层只有 1–32 对（共 11.8M 对）。dense 模型里没有「激活相同可相加」的冗余单元；Goodfire 的「神经元模式」是功能语义聚类，不是可合并的重复件。

R9 逐层预算分配：单层敏感度差 30 倍（layer 0 keep 0.2 → +816.8%；layer 9 keep 0.2 → +2.3%；layer 23 keep 0.2 → +28.7%）。贪心分配 vs 均匀：全局稀疏 10% 时 +5.65% vs +15.35%（2.7×）、20% 时 +23.25% vs +43.85%（1.9×）、30% 时 +44.75% vs +86.71%、40% 时 +98.42% vs +179.00%。分配值 ~2× 改善，但 10% 稀疏仍不免费，且高稀疏度下贪心把个别层推到 0.2 下限后反而失效（7B 的 S=0.2：分配 +29.15% 差于均匀 +23.24%）。

R10/R11 选择量（keep 0.95 / 0.90 / 0.85）：energy +4.83% / +13.17% / +28.20%；p99 +13.89% / +40.31% / +59.34%；tail（P(>q90)）+30.55% / +59.20% / +82.99%；deg（top-32 共激活度数）+9.63% / +23.33% / +38.94%；deg（top-64）+16.75% / +41.73% / +66.38%。连接度是文献审计里唯一的「真空隙」（以共激活图度数排序做权重剪枝无直接工作），实测判负。

7B keep 0.8（剪 20%） +23.24% +7.38% −12.29%

恢复能买回 ~68–73% 的伤害，但 20% 剪枝仍留 +7~12%；50% 用朴素 SGD 直接发散。Goodfire 的量级是 100M token（91M SFT + 9M RL），比 200 步（≈0.1M token）大 3 个数量级。

R13 训练式非线性路由器（4B，d→64→I，16k token，3 epoch）：召回 0.65–0.76（random 0.60），端到端（4 个路由层 + 其余 oracle）+12.63%。规模不但没有让路由更容易，反而更接近随机（见 §3.3）。

3.3 反直觉 / 负结果

（1）规模效应只出现在「不可兑现」的那条线。 静态免费空间几乎不随规模变（0.5B ≈2%、4B ≈3%、7B ≈2.5%）；动态 oracle 从 20–30% 涨到 ~40%；而路由可预测性随规模变差——1.5B 召回 0.903–0.914（random 0.900）、4B 0.854（random 0.850），相对随机基线的优势被抹平。唯一变大的蛋糕恰好是吃不到的那块，这是整条线最反直觉的结构。

（2）「免费」的 40% 是激活计算的性质，不是可兑现的资源。 oracle 需要先算完全部激活才能选 top-k；任何从层输入预测 top-k 的尝试（线性、gate-only、非线性 MLP）要么端到端崩（+12.6%~+191.7%），要么只省 6–9% 且需要硬件支持。这条结论在 0.5B/1.5B/4B/7B 上一致，也是判死「动态门控可兑现」的核心依据。

（3）神经元近正交，结构合并没有冗余可吃。 这解释了为什么 R5/R6 不是工程实现问题，而是「dense 模型里没有可合并单元」这个事实问题。同时它反过来说明 Goodfire 的结论依赖 MoE：35B-A3B 的专家冗余在 dense 模型里没有对应物。

（4）recovery 真实存在，但买不回免费。 剪 20% + 200 步从 +43.85% 压到 +11.79%（7B 从 +23.24% 到 +7.38%），方向是对的；但剪 50% 发散，且 Goodfire 的恢复预算大 3 个数量级。代谢账本上，recovery 是「重新学习捕食」——它是唯一可能产生真食物的环节，但本轮的分钟级版本不够。

（5）一个被数值复核抓到的假阳性（方法论负结果）。 R10 的 deg/tail 属于「计数型」重要性，有大量并列值：layer 0 有 1,822/4,864 个神经元 top-32 计数为 0，末层 89% 为 0。用阈值 sc >= topk(k).values.min() 构造 mask 会保留全部神经元 = 根本没剪，一度伪造出「deg 在 keep 0.95 只 +0.31%、远优于 energy」的假象；改成精确 top-k 索引后是 +9.63%（更差）。规则：计数型重要性必须用精确 top-k 索引做 mask，不能依赖阈值比较。同类的还有「恢复实验必须先物理置零再评估」——微调会把被剪权重长回来。

4. 结论与判定

判定：判负。 判死的假设不是「LLM 激活是稀疏的」（R3 证明它确实稀疏），而是「这种逐 token 稀疏可以变成静态可部署的资源」，以及它的三个替代形态（合并、组级、学习式路由）。四条路线在 0.5B/1.5B/4B/7B 上结论一致；规模只扩大了不可兑现的那部分。判定阈值是「≤1% PPL 代价」与「省算力 > 近似误差」，实测：静态 2–3%、动态 40% 仅 oracle、合并误差 +34.3~+8836%、组级误差 +18.2~+105%。

可写（支持的结论）

  1. 「重排」成立且无损（R0：+1.1e-3），所以「按激活重排权重」这件事本身可以做；但「逐步清空」在静态意义下只值 2–3%（keep 0.98 时 0.5B +0.87%、4B +0.25%、7B +0.63%）。
  2. 免费空间与规模的交互是方向性的：静态几乎不随规模变（2–3%），动态 oracle 从 0.5B 的 20–30% 涨到 4B/7B 的 ~40%——但后者仅存在于 oracle，不能作为可达指标。
  3. 三条结构性替代全部劣于静态剪枝：合并（R6 +34.3% @10%，2.5× 差）、组级（R8 G=256 keep75% +7.6~18.2% 而理论只省 16.7%）、学习式路由（R13 +12.63% 端到端）。适用条件：dense FFN、wikitext 域、PPL 判定。
  4. 分钟级 recovery 能把 20% 剪枝的伤害从 +43.85% 压到 +11.79%（7B：+23.24%→+7.38%），方向真实但不足以把剪枝变成免费。

不可写（诚实边界）

  1. 不能说「剪枝对模型能力无害」：全部判定基于 held-out PPL。已有反例（INT6 下仅 51.3% 活跃 SAE 特征存活；GPT-2 剪 30% 神经元使 IOI 电路反转）说明 PPL 会漏掉能力损伤；本轮没有自测端到端答案与行为检查（只在文献里引述 Q3 类）。
  2. 不能说「40% 稀疏可用」：它只是 oracle 上界，且与可兑现算力之间隔着「先算完全部激活」这道不可绕过的成本。
  3. 不能说「规模越大越好剪」：静态免费空间在 4 个规模上都是 2–3%，唯一的增长在 oracle 线上；路由可预测性反而随规模变差（1.5B 0.903 vs random 0.900）。另需注意口径：4B/7B 的「免费 3%/2.5%」是在 keep 0.98 与 0.95 两个测点之间插值，没有在 1% 容差处直接测 keep 0.97。
  4. 不能说「Goodfire 的 92.2% 被复现或推翻」：那是 MoE + 动态 + 100M token recovery 的组合，本轮只检验了它在 dense 静态场景下的三个前提，且三个都不成立。

对后续决策的含义：剪枝/条件计算这条线停止投入，只保留两个方向——A 改架构：路由器与专家联合训练（MoE 式），用训练换可兑现的稀疏，但那不再是剪枝；B 换问题：把稀疏性当分析/可解释性工具，主线回到 memory-jev 的端到端答案（代谢审计指出的最大盲区：从未测过答案正确率）。

6. 未做 / 下一步

  • 端到端答案没测：没有 LME_s 的 EM/F1 + citation，也没有「压缩后能否住进更小身体」的实际部署验证；pt / joule 账本只搭了口径，没有真实焦耳数。
  • 行为检查只做了 Q3 类文献引述，本模型上没有系统测推理循环率/回答长度（--keeps 0.8 --steps 200 之外未做）。
  • M-1 跨域稳定性预检未跑：原计划用它证伪「一次校准剪全局」，但静态免费空间只有 2% 之后这条已不构成瓶颈（计划 §6.1 的优先级下调）。
  • 真实 kernel 未测：1080 Ti 无 Triton，「只算 gate 排序」与 gather 形态的实际加速没有测；这需要 AutoDL 新卡 + 专门内核。
  • SparseGPT/OBS 类二阶重建未复现：本轮只做「置零」剪枝，没有做权重重建，因此「静态免费空间只有 2–3%」的边界是「无重建的静态剪枝」；文献里 60% 近无损依赖二阶重建，不属本结论。
  • 恢复预算未扫：200 步是单点；未扫 1k/10k 步与 LoRA 式恢复，也未测「恢复后行为」是否同步恢复。
  • MoE 侧未验证：本轮所有模型都是 dense，Goodfire 的 MoE 冗余假设无法在本地检验（需要 35B-A3B 级模型与多卡）。
