# E0 可靠性工装：先证明「打分器」可信，再花 GPU 的钱

> **一句话**：TQR 打分器被发现恒返常数、任何「可靠性/判别力」测量都会假性满分 →
> 在本地用纯标准库写了特征抽取 + 度量 harness（逐条独立打分、ICC(2,1)、位置稳健、池敏感性）→
> σ=0.15 下 ICC=0.9940 / 顺序 rho=0.9830 / 翻转率 0.000，G0 PASS →
> 但前提是"打分噪声来自真 judge"，桩特征的 ICC 只证明工装自洽，不证明判别力。

## 0. 摘要

E0 要回答的不是"TQR 分数好不好"，而是**在这个分数上做任何测量之前，尺子本身会不会永远给同一个读数**。
检查 `Stellan_Core/sub_agent_framework/base_agent.py:168` 的 `evaluate_tqr()` 后发现它用全默认 `TQRScore()`、
从不读 node，因此任意节点恒返 `9.176056742068813`：候选池内所有分数相同，排序退化为「取第一个」，
ICC 必然 = 1.0（假信号），E1 的 AUROC 必然 = 0.5，硬阈值 `>10.0` 永不触发。

在不连远端、不花钱的前提下交付两个纯标准库文件：`features.py`（六特征，Law-II 边界内）与
`e0_harness.py`（ICC(2,1) / 位置交换 / 池敏感性 / 可控噪声 judge）。12 个样例节点 × 5 次重复 × 40 次打乱下，
σ=0.15 得 ICC=0.9940、翻转率 0.000、顺序 rho=0.9830，**G0 PASS**。

最重要的产出不是那个 PASS，而是**阴性对照推翻了原判据**：给 judge 注入位置偏置后 top-1 翻转率几乎不动
（bias=0.20 时才 0.075），而顺序一致性 rho 从 0.9830 掉到 0.8582。所以位置稳健性的主判据必须换成 `rho >= 0.95`。

| 实验 | 问题 | 结果 | 判定 |
|---|---|---|---|
| E0-a | 打分器是否只是常数？ | 任意节点恒返 9.176056742068813 | 判负（前置阻塞） |
| E0-b | 逐条独立打分下重测一致性？ | ICC(2,1)=0.9940（σ=0.15） | ✅ |
| E0-c | 换呈现顺序会不会翻 top-1？ | 翻转率 0.000，顺序 rho=0.9830 | ✅ |
| E0-d | 工装能否检出位置偏置？ | bias=0.20 → rho=0.8582，G0 FAIL | ✅（阴性对照通过） |
| E0-e | 小候选池（k=4）排序可信吗？ | rho=0.945；σ=0.40 时 worst rho=−0.400 | ⚠️ 未进 G0 判据 |

## 1. 问题与假设

**决策问题**：要不要在这个打分器上继续投入（下载模型、租 4090、跑 E1 的 LLM-judge）？
如果尺子本身不可信，后面所有 AUROC / ICC 都是花钱买假信号，所以先花零成本把尺子验掉。

已确认的三个连锁后果（均来自源码阅读，不是推测）：

- 候选池内所有 `tqr_score` 相同 → `max(alternatives, key=...tqr_score)` 退化为「取第一个」；
- E0 的 ICC 必然 = 1.0（测的是常数，不是可靠性）；
- E1 的 AUROC 必然 = 0.5；`base_agent.py:255` 魔鬼代言人的硬阈值 `>10.0` 在默认 context 下永不触发（9.176 < 10）。

**预注册判据（G0）**：

| 指标 | PASS 阈值 | 来源 |
|---|---|---|
| ICC(2,1) | `>= 0.70` | `E0.md` §3 / `e0_harness.py` 头部注释 |
| top-1 位置翻转率 | `<= 0.15` | 同上 |
| 顺序一致性 rho | `>= 0.95`（本轮新增） | `PROGRESS.md` 2026-10-06「E0 改动」 |

第三条是本轮**改了判据之后**才加进去的，理由见 §3.2。

## 2. 实验设置

### 2.1 环境

- 平台：本地 Mac，**零 GPU、零远端连接、零花费**。用户明确选「不开机、本地推进」。
- 依赖：**纯标准库**（无 numpy、无 torch），两个文件可原样拷进 `Stellan/tqr_guided_rl/src/tqr/`。
- 运行：`python3 e0_harness.py`（默认 `--sigma 0.15`，可选 `--sigma 0.40`、`--bias`、`--reps`、`--seed`）。
- 复现性：同种子两次运行输出 md5 一致（本轮早期版本 `7db8f0aa...`；改成逐条独立打分后的版本 `6fee94b5...`，
  两值分属两次改动，不能互相当校验）。

### 2.2 模型与数据

**没有模型、没有数据集**——这正是本实验能零成本的原因。

- 打分对象：`e0_harness.py` 里的 12 条手写样例节点（`NODES`），故意覆盖长/短、确定性/对冲、
  数学推理与套话（例如 `"2 + 2 = 4"`、`"Maybe the answer is 5, but I am not sure..."`、
  `"This is a very important step. " * 6`）。
- 特征抽取：`features.py` 的 `features(text) -> 6 特征`，只用 `math`；`tqr(f)` 合成最终分。
- 规模：12 items × 5 reps（ICC 的 `M[rep][item]`）× 40 轮打乱（位置交换与池敏感性共用轮数）。

### 2.3 方法

**特征与打分**（`features.py`，Law-II 边界内）：

| 特征 | 含义 | 取值范围 |
|---|---|---|
| `alpha` | 词数对数饱和 | `[0,10]` |
| `beta_r` | 平均词长接近 5 的惩罚 | `[0,1]` |
| `beta_n` | 长度 × 子句密度 | `[1,10]` |
| `delta` | 对冲词密度（maybe / might / perhaps / possibly / unsure / guess / assume） | `[0,0.95]` |
| `complexity` | 长度饱和 | `[1,10]` |

$TQR = \dfrac{(\alpha\beta_r)^{w_r}\cdot\beta_n^{w_n}\cdot(1-\delta)^{w_d}}{\ln(e + c\cdot k)}$

**可控噪声 judge**（`judge()`）：只给**单个节点**打分，不传全池；按高斯噪声扰动特征后 clamp 回边界，
再算 TQR。默认 `sigma=0.15`，其中 `alpha` / `beta_n` 用 `σ`，`beta_r` / `delta` 用 `σ/5`。
可选乘性位置偏置：$s' = s\cdot(1 + b\cdot \text{pos})$，`pos` 是呈现序号。

**四个度量**：

1. `icc21(M)`：双向 ANOVA 的 ICC(2,1)，`M[rep][item]`。
   $ICC(2,1)=\dfrac{MS_R-MSE}{MS_R+(n-1)MSE+n(MS_C-MSE)/k}$，n=5 reps，k=12 items。
2. `position_swap()`：**逐节点独立打分**后比较不同呈现顺序；返回 `(baseline top-1, 翻转率, 平均 rho)`。
   rho 是基线分向量与乱序后分向量的 Spearman。
3. `pool_sensitivity()`：**同一批候选**的子集排名 vs **全池**排名的 Spearman（k=4/8/12，40 轮），
   报 mean 与 worst。
4. `judge()` 本身即「可控噪声源」，用 σ 模拟 LLM-judge 的不可约随机性。

**判定**：`icc >= 0.70 and flip <= 0.15 and rho >= 0.95` 才 PASS（`e0_harness.py` 末尾）。
**没有** bootstrap、没有多种子置信区间、没有 label shuffle —— 见 §6。

## 3. 结果

### 3.1 主结果

12 节点 / 5 reps / 40 轮打乱，同一 `seed=0`：

| 配置 | 指标 | 数值 | 95% CI | 判定 |
|---|---|---|---|---|
| σ=0.05 | ICC(2,1) | 0.9993 | 未记录 | ✅ |
| σ=0.15（默认） | ICC(2,1) | **0.9940** | 未记录 | ✅ |
| σ=0.40（高噪声） | ICC(2,1) | 0.9573 | 未记录 | ✅ |
| σ=0.05 | 位置翻转率 | 0.000 | 未记录 | ✅ |
| σ=0.15 | 位置翻转率 | **0.000** | 未记录 | ✅ |
| σ=0.40 | 位置翻转率 | 0.000 | 未记录 | ✅ |
| σ=0.05 | 顺序一致性 rho | 0.9983 | 未记录 | ✅ |
| σ=0.15 | 顺序一致性 rho | **0.9830** | 未记录 | ✅ |
| σ=0.40 | 顺序一致性 rho | 0.8869 | 未记录 | ❌（跌破 0.95） |
| σ=0.15 | 池敏感性 rho（k=4） | 0.945 | 未记录 | 仅诊断 |
| σ=0.15 | 池敏感性 rho（k=8） | 0.980 | 未记录 | 仅诊断 |
| σ=0.15 | 池敏感性 rho（k=12） | 0.984 | 未记录 | 仅诊断 |

- **G0 判定：PASS**（ICC 0.9940 ≥ 0.70、翻转 0.000 ≤ 0.15、rho 0.9830 ≥ 0.95）。
- 其它实测值：`within-item sd = 0.3258`（同一节点的 5 次重复 sd 的均值）；`mean score` 未记录；
  `features.py` 在样例上 TQR 实际跨度 **0.34–22.18**（这是"分数不再恒定"的直接证据）。
- σ=0.40 时 k=4 的 **worst rho = −0.400**（`PROGRESS.md` 2026-10-06「E0 工具链」实测行），
  即高噪声 + 小候选池下子集排名可能与全池排名**负相关**。

### 3.2 对照与消融

**（a）位置偏置阴性对照**：给 judge 注入 `s *= 1 + bias * position`，看工装能不能检出被写坏的情况。

| bias | top-1 翻转率 | 顺序一致性 rho | 判定 |
|---|---|---|---|
| 0.00 | 0.000 | 0.9830 | ✅ |
| 0.05 | 0.000 | 0.9545 | ✅（擦线） |
| 0.10 | 0.000 | 0.9031 | ❌ |
| 0.20 | 0.075 | **0.8582** | ❌ |
| 0.40 | 0.150 | 0.8086 | ❌ |

结论：**top-1 翻转率对位置偏置几乎无感**（bias 到 0.20 才 7.5%，仍在 15% 判据内），
而顺序一致性 rho 敏感得多（0.9830 → 0.8086）。因此 rho 才是有效判据，翻转率只能当辅助。
这也是预注册判据从「翻转率 ≤ 15%」扩成「翻转率 + rho 双阈值」的直接原因。

**（b）自检**：bias=0.20 时 G0 判 FAIL（翻转 0.075 仍合格但 rho=0.8582 跌破 0.95）——
工装**能正确检出**被污染的打分器，不是只会 PASS。

**（c）噪声水平消融**：σ=0.05 / 0.15 / 0.40 三档，ICC 从 0.9993 单调降到 0.9573，
说明 ICC 确实在测"噪声/信号比"，而不是在测常数。

### 3.3 反直觉 / 负结果

1. **原判据是错的**（最重要的负结果）：位置交换一致率 > 15% 这条阈值对位置偏置过于宽松，
   靠它会在 rho 已经烂到 0.86 时继续放行。判据失效，不是数据失效。
2. **「ICC 高」不等于「打分器好」**：确定性打分器的 ICC 恒为 1.0，这是假信号；
   E0 的有意义版本必须来自打分函数的**真实噪声**（真 LLM-judge 采样），harness 里的 σ 只是模拟。
3. **k=4 小池排序不可靠**：σ=0.40 时 worst rho=−0.400；σ=0.15 时 mean rho=0.945 也已低于 0.95。
   而 E1 的实际候选池通常只有几个，这个数字比全池 ICC 更接近真实使用场景。
4. **翻转率这个指标基本没用**：它在全部 bias 档位里只从 0.000 走到 0.150，
   无法区分"完全正常"和"顺序一致性已经崩了"。

## 4. 结论与判定

- **判定：完成**。G0 在默认配置下 PASS（ICC 0.9940 / flip 0.000 / rho 0.9830），
  阴性对照能检出污染（bias=0.20 → FAIL），工装本身可用。
- **可写（支持的结论）**：
  1. 修复"打分器不读 node"之后，TQR 分数在 12 条样例上跨度 0.34–22.18，**不再是常数**；
     原实现任意节点恒返 9.176056742068813，这一条是可复现的缺陷，不是推测。
  2. 逐条独立打分 + 高斯噪声 σ=0.15 时，ICC(2,1)=0.9940、顺序 rho=0.9830、翻转率 0.000。
  3. **位置稳健性的主判据应是顺序一致性 rho（≥ 0.95），不是 top-1 翻转率**；
     依据是阴性对照里翻转率对偏置不敏感（bias 0.20 仍 0.075）。
  4. 小池敏感性可测（k=4 mean rho 0.945 / k=8 0.980 / k=12 0.984），但当前未纳入 G0。
- **不可写（诚实边界）**：
  1. **不能**说"TQR 打分器有判别力"。本版特征是"有区分度且可复现"的代理，无语义真值；
     H2（判别力）要等 E1 换成 LLM-judge / 人工标注。
  2. **不能**把 ICC=0.9940 当成"真 judge 也这么稳"。σ 是人为设定的模拟值，
     真 judge 的采样噪声未实测；接真 judge 时必须把 σ 换成实测值重跑。
  3. **不能**说"位置稳健性没问题"。σ=0.15 下成立；σ=0.40 下 rho 已 0.8869，属 FAIL。
  4. **不能**说"小候选池排序可信"。k=4 在 σ=0.15 已 0.945、σ=0.40 worst −0.400。
- **对后续决策的含义**：可以继续（工装已就位、生产补丁已写成参考实现），
  但 E1 之前必须先解决"真 judge 噪声"这件事；未解决则一切 ICC 都是自证。

## 5. 踩坑与修正

| 现象 | 根因 | 解法 |
|---|---|---|
| `icc21` 算出 ICC=−0.0001（假阴性） | 把 `M[item][rep]` 当成 `M[rep][item]`，SSR/SSC 互换 | 打印 MSR/MSE/MSC：MSC=150 而 MSR=0.16，与「5 reps × 12 items」形状不符；修正后 σ=0.15 得 0.9940 |
| 池敏感性出现负 rho | 初版比较"不同子集各自的排名"，k 越大越不可比 | 改为**同一批候选**：子集排名 vs 全池排名的 Spearman |
| `within-rep sd` = 5.48，被节点差异主导 | 原式跨节点算 sd，不是重复测量的 sd | 改为**同一节点**的重复 sd，得 0.3258 |
| `position_swap` 仍返回 2 个值 | 新旧定义共存（Python 后定义覆盖前者），删重复块时又误删新版 | 重写并核对**最终生效的定义**；教训：改写后要检查实际被调用的那一份 |
| 脚本写不进文件（>~800 字节或含全角标点即卡 300s） | 本地执行环境限制（单次命令约 200–300 字符上限） | 逐行小批量 `printf ... >> file`；二进制/长内容走 base64 单行解码 |
| 生产补丁无法落地 Stellan | `Stellan_Core` 目录无写权限（`Operation not permitted`） | 补丁留在 `E0.md` §4 作参考实现；按用户决定**不写入** Stellan |

另外两条与环境相关、但不影响结论的坑：`printf` 与较长 heredoc 会挂起（改用短 `echo`），
反引号会被 shell 求值导致内容被污染（写入时一律避开反引号）。

## 6. 未做 / 下一步

1. **E1 暂缓**：把桩特征换成 LLM-judge / 人工标注，才能测 H2 判别力。这是唯一能回答
   "TQR 分数到底有没有用"的实验，本文件不覆盖。
2. **生产补丁未落 Stellan**：`TQRFeatureScorer` + 新的 `evaluate_tqr()` 已写在 `E0.md` §4，
   但按用户 2026-10-06 决定不写入（该目录也无写权限）；兼容性：新参数全部有默认值，
   现有 31 处 `tqr_score` 读取方不受影响，但**分数分布会变**，`>10.0` / `<1.0` 两个硬阈值需重标定。
3. **池敏感性未进 G0**：建议补一条（如 k=4 mean rho ≥ 0.8），因为它才是"小候选池下排序是否可信"的直接度量。
4. **真 judge 的 σ 未实测**：本 harness 的噪声是模拟；接真 judge 后必须标定 σ 再重跑 ICC 与 rho。
5. **无置信区间**：没有 bootstrap、没有多种子（只有 `seed=0`），表中 CI 列只能写「未记录」。
6. **无 label shuffle / 随机特征对照**：本实验的对照只有位置偏置与噪声档位，语义层对照留给 E1。
