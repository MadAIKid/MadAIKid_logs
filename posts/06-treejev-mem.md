# TreeJev-Mem：12 条硬约束如何把「树 + 共鸣 + 标签器」逼成一个可判死的记忆层

> **一句话**：记忆的瓶颈不是编码器，而是「什么值得写、按什么顺序读、跨轮证据怎么传」；12 条来自两篇前作的硬约束把设计逼成「三级树 + 两遍门 + 锐化共鸣 + 写入端标签器」，CPU 原型三档跑通（free 0.912 / no-state 0.050），但图审的数值复核推翻了「多步共鸣」——它是负优化（cos 0.754→0.612）；J 系列最终把收益落在逐跳 meta 寻址（+26.5pt），而端到端答案正确率始终未测。

## 0. 摘要

这条线要回答的是「记忆层还值不值得继续投入」，而不是「能不能做一个更大的 retriever」。做法是先把两个前作已验证的事实（`recursive-jev-rag` 的 6 条证据状态信道结论、本仓库 prompt-JEV pilot 的 4 条读出结论）与两条命名纪律固化成 12 条硬约束，再让架构逐条满足它们。结果是三层的组件分工基本成立（树负责候选集、共鸣负责跨轮状态、JEV-style 头负责判定与弃权），但每个组件的「免费收益」都比图上小得多：多步共鸣按预注册判据判伪，树只在 ≥3.4k items 占优，真实数据上真正的瓶颈是标签质量（evidence AUROC 0.677）而不是嵌入或寻址。判定为**部分完成**：E1–E3 有结论、J1–J9 有数字，但 E4–E7 未跑，端到端答案正确率一次都没测。

## 1. 问题与假设

**决策问题**：在已经知道「检索层接近饱和」的前提下，是否还值得为一条新的记忆层投入 ~24 GPU-h（≈ ¥70）？具体拆成三个可判死的子问题：

1. 树结构在同等 token/延迟预算下是否真的比平铺好（E1）；
2. 潜向量共鸣的多步迭代是否比单步 feedback / 原始 query 更好（E2）；
3. 「JEV 模型识别 meta 标签 → 标签辅助寻址」这条用户思路是否成立（J1→J2→J3→J5）。

**设计约束的来源**。12 条硬约束先于架构确定，没有一条要求更大的模型，全部要求状态/预算/评测协议的设计正确（这也是 48G 单卡能做的部分）：

| # | 已验证事实（带出处数字） | 逼出来的设计 |
|---|---|---|
| C1 | global KV 比逐层 KV 小 12×（1,536 vs 18,432 B/token），质量只差 0.09 bpb | 单一共享状态，不为每层/每轮存摘要 |
| C2 | KV 4-bit 近免费（+0.0001 bpb）；2-bit 玩具实验 free 4-bit 0.925 vs 2-bit 0.490 | 判决分数 4-bit；2-bit 对决策信号过粗 |
| C3 | 时序低通（m8）代价 +0.130/+0.055 bpb，远高于量化 | 预算不够先量化，不丢时序/层级 |
| C4 | 近无损 latent 不可预测（Cola2-lite prior 6.07 vs 回退 1.82） | 状态只存 answer-bearing 抽取式 claim + 引用 |
| C5 | oracle vs free gap（1.41/3.22 vs 11.75/12.38 bpb） | free-running 是主指标，oracle 上界、no-state 下界 |
| C6 | 无 fallback 会崩（8.91→2.19 bpb）；judge 错误 8%→25% 时 0.925→0.734 | 三态 + fail-open + 早停 |
| C7 | readout gap：线性探针 0.916 acc / 0.966 AUROC vs 受限 softmax 0.777，峰值在 L23 0.934 | 判定用 h_T 探针读出，不信模型自报概率 |
| C8 | 跨选项顺序迁移仅 0.472/0.257，方向余弦 0.154（但行为一致率 0.940） | 模板固定或格式增广，不宣称通用判断向量 |
| C9 | K=2 最稳（0.839，flip 4.1%）；K=3 适合 noul（0.902 @ 80% 覆盖）；头+探针 stack 最优 | 二值筛 K=2、弃权 K=3、终选 stack |
| C10 | 探针信息几乎全在 LM head letter 子空间外（去掉子空间 0.931→0.929） | 头是读出/校准组件，不是控制手段 |
| C11 | JEV 接口是（文本 state, 问题）→ typed decision；公开实现 acc 0.541；厂商概率不可信 | JEV 只作 teacher/契约；运行时改叫 JEV-style zero-generation decision head |
| C12 | 冻结 LM 的判断与 text JEV 不是一回事，teacher 自述是弱标签 | 标签优先级：合成 gold > 反事实效用差 > 探针伪标签 > teacher 自述 |

**预注册 kill criteria**（跑之前写死，见 §4 逐条结算）：E1 树相对平铺 free-running 增益 <2pt ⇒ 砍树；E2 相对 max(R=1, 原始 q0) 增益 <1.5pt ⇒ 判伪；E3 4-bit 与 16-bit 差 >0.5pt ⇒ 改 8-bit；E4 注入 10% 门错误后掉 >10pt ⇒ 必须上 verifier；E5 后训练提升 <2pt ⇒ 判负；E6 empty 态 fail-open 不如直接弃权 ⇒ 改协议；E7 oracle-free gap <3pt ⇒ 该任务不需要递归状态。

**为什么怀疑已有做法**：文献里「层级 typed gate + 弃权」（NDM）、「latent memory tree + RL」（ActiveMem）、「跨轮潜向量 query 精炼」（SQR/CAST）、「嵌入写入门」（MemRouter）都各自被做过，组件层没有一个新东西；可辩护的只能是耦合方式（N1 逐层 typed gate、N2 gate 概率控制迭代预算、N3 同编码器 MRL 分层、N4 risk-coverage 评测）。因此本轮先做**证伪**：如果 oracle meta 标签都不涨，整条 v3 路线不成立。

## 2. 实验设置

### 2.1 环境

- GPU：AutoDL 实例 `westb`，RTX 4090 48G；EG2 文本塔 bf16（271,002,624 参数）load 6.0s，3 条短文本编码 0.43s，MRL 128/256/512/768 截断后 norm=1.000。
- CPU 冒烟：`weste` 无卡模式，**1 CPU 核 + cgroup 内存 2GB**（`memory.max=2147483648`），只验证代码路径，不做语义结论。
- 计划成本 ~24 GPU-h ≈ ¥70；实际记账不完整（04:30 记「累计约 70 min ≈ ¥3.5」，之后未再记）。

### 2.2 模型与数据

- 编码器：`google/embeddinggemma-2`（1.5G，768d，bf16-only，MRL 128/256/512/768）。
- 判定/生成：`Qwen3-4B-Base`（G2 探针）、`Qwen3-4B-Instruct-2507`（生成）。
- 标签器：`embeddinggemma-2-ft-typed-decision`（1.1G 底座）+ 记忆 meta 全参后训 36s ⇒ `eg2-td-meta-ft`（体积两处文档记 550M 与 1.1GB，未核）。
- 数据（转换后）：LME oracle 10,960 items / 500 q；LME_s 246,750 / 500；LoCoMo 5,882 / 1,986；MuSiQue+2Wiki 299,835 / 27,569（14,993 pairs）；MemoryAgentBench 114,952 / 3,671；NFCorpus 3,633 / 323；合成记忆流可无限生成。

### 2.3 方法

**三级树**（图审后定稿）：`root(0) → 时间桶 bucket(1, 128d) → 桶内语义簇 cluster(2, 256d) → claim 叶(3, 768d)`，另加跨桶同簇边（廉价版 propagation）；512d 层降级为「可选 episode 层」，v1 不实现。

**两遍门**（修掉 v1 的循环依赖）：G0 用 MRL 多尺度 cosine 免费粗筛 → G1a 激活门（特征 `[q_r; k_i; Δt; level; modality]`，**不用 s**）→ 共鸣 → G1b 判定门（用 `s_r`）→ G2 只在叶层（≤16 候选，因为 C4 规定内节点不存自由摘要）。

**锐化共鸣**：

$$w_i=\frac{a_i^{p}}{\sum_{j\in \text{top-}m} a_j^{p}},\qquad s \leftarrow N\big((1-\lambda)s+\lambda\sum_i w_iV_i\big)$$

默认 λ=0.2、p=4、m=3、R≤4；`cos(s,q0)<0.5` 触发漂移回退。共鸣只负责聚合，正确性归 G2 判定——图审同时删掉了「能量极小 = 召回正确」的假设（能量景观的全局极小天然是高频干扰记忆）。

**meta 寻址**：图审后放弃「全局标签拼进向量」，改为 $score=cos(内容)+\lambda\cdot meta\_match(query\_need, item\_meta)$，λ≈0.02。

**后训练**：Stage A 只训 heads（冻结编码器）；Stage B 文本塔全参（InfoNCE/MRL + 共鸣一致性 + 门蒸馏，**bs 32–64**，官方 cookbook 的 bs=1 是 3 条样本的 demo）；anchor 损失把 tuned embedding 拉回冻结 EG2。

## 3. 结果

### 3.1 主结果

J 系列是这条线唯一有可复现正收益的部分：meta 的价值在**逐跳消歧**（bridge vs terminal、关系槽），不在全局向量拼接。

| 配置 | 指标 | 数值 | 95% CI | 判定 |
|---|---|---|---|---|
| content-only（J1b，267 steps） | top-1 | 0.2135 | 未记录 | 基线 |
| + oracle meta λ=0.02（J1b） | top-1 | **0.5019（+28.8pt）** | 未记录 | ✅ |
| + 4B h_T 预测 meta λ=0.02（J2） | top-1 | 0.5019（=oracle） | 未记录 | ✅ |
| content-only（J5，170 steps / 62 题 / Σ150 query） | top-1 | 0.2529 | 未记录 | 基线 |
| + 后训 labeler 预测 meta λ=0.02（J5） | top-1 | **0.5176（+26.5pt）** | 未记录 | ✅ |
| + pred meta λ=0.05（J5） | top-1 | 0.4353 | 未记录 | 与 oracle 相同 |
| + oracle meta λ=0.05（J5） | top-1 | 0.4353 | 未记录 | — |
| 75% 标签随机替换（J5，λ=0.05） | top-1 | 0.4529 | 未记录 | 意外鲁棒 |
| 100% 标签随机（J5，λ=0.05） | top-1 | 0.2529 | 未记录 | 回落 = content |

两点值得单独记：λ 比标签质量更敏感（λ=0.02 是 0.5176，λ=0.05 掉到 0.4353）；meta 只作离散 tie-break，所以 75% 标签被随机替换仍不掉点。

### 3.2 对照与消融

**CPU 原型三档（mock encoder，只验证管线，数字不代表语义能力）**：

| mode | acc | hop | update | abstain | evidence_recall | avg_rounds | avg_bits |
|---|---|---|---|---|---|---|---|
| oracle | 1.000 | 1.0 | 1.0 | 1.0 | 1.00 | 1.0 | 67 |
| **free** | **0.912** | 0.848 | 1.0 | 1.0 | 0.95 | 2.42 | 141 |
| no_state | 0.050 | 0.0 | 0.0 | 0.2 | 0.12 | 1.0 | 12 |

方向符合 C5（oracle > free ≫ no_state；no-state 在多跳上接近随机）。冒烟同时暴露两个「组件未被考到」的信号：共鸣 R=1/2/4 完全不变（free 恒 0.912），只有 feedback both vs none 有效（0.912 vs 0.850，+6.2pt）；量化非单调（16b/8b 0.875、4b 0.912、2b 0.938，n=80，差异在噪声内）。

**E1 树 vs 平铺（真实 EG2，同一脚本换规模）**：

| 记忆规模 | 树 acc | 平铺 acc | 树 hop | 平铺 hop | 树打分节点 | 平铺打分节点 |
|---|---|---|---|---|---|---|
| 458 items | 0.7875 | **0.8000** | 0.630 | **0.652** | 887.7 | 1,144.8 |
| 3,265 items | **0.8500** | 0.7750 | **0.714** | 0.571 | 1,740.3 | 7,358.9 |
| 9,397 items | **0.9125** | 0.5375 | **0.868** | 0.302 | 2,286.5 | 24,384.1 |

小规模时树的路由约束反而漏候选（−1.3pt）；3.4k 起树 +7.5pt（hop +14.3pt）且打分节点只有平铺 1/4.2；9.4k 时 +37.5pt、节点差 10.7×。方向对，但「规模越大树越赢」是趋势而非定律。

**E2 共鸣深度 × feedback（真实 EG2）**：

| 配置 | 458 items | 3,265 items | 9,397 items |
|---|---|---|---|
| R=0 / feedback none | 0.7500 | 0.8375 | **0.9375** |
| R=1 both | **0.7875**（+3.7pt） | **0.8500**（+1.2pt） | 0.9125 |
| R=2 / R=4 both | 0.7875（与 R=1 相同） | 0.8500（相同） | 0.9125（相同） |
| R=1/2/4 none | 0.7500 | 0.8375 | 0.9375 |

多步迭代在三个规模上都没有任何增量 → 按 §8.5 判伪。**单步 feedback 也不稳**：458 与 3.4k 是 +3.7/+1.2pt，9.4k 上无共鸣（0.9375）反而比有共鸣（0.9125）高 2.5pt——文档没有判读这一档，本实验只记录原始数字，不做因果解释。

**E3 量化**：三档规模复现同一反常——16b/8b/4b 相同，2-bit 反而更高（458 items：0.7875/0.7875/0.7875/0.9125；3.4k：0.85/0.85/0.85/0.9125；9.4k 四档均 0.9125）。诊断为 confound：量化只作用在排序键上，粗量化制造 ties 改变了提交顺序，没有真正考到状态信道。按预注册口径这条实验**不可判**，需要把量化后的分数作为下游状态输入重做。

**真实检索（100 题 LME_s / 200 题 LoCoMo，EG2 bf16）**：

| 数据 | 平均池 | 平铺 recall@10 | 默认树 b8/c16 recall@10 | 平铺 MRR | 树 MRR |
|---|---|---|---|---|---|
| LME oracle（489 题） | 22.7 | 0.9341 | 0.9341 | 0.7041 | 0.7041 |
| LME_s | 720.5 | **0.8750** | 0.8156 | **0.7142** | 0.6595 |
| LoCoMo | 418.8 | **0.6069** | 0.5328 | **0.3788** | 0.3333 |

默认 b8/c16 在真实数据上明显丢召回（LME_s −5.9pt，LoCoMo −7.4pt）：时间桶先切导致 40 个桶里 top-8 只覆盖 20% 池。60 题路由扫描显示加宽可打平（b32/c64：recall@10 0.9667、MRR 0.7916、516.6 节点；语义树 b1/c16 同召回但 435.5 节点，比时间树省 16%；平铺 0.9667/0.7888/732.9 节点），而 RRF(向量+BM25) 把 recall@10 拉到 1.000、MRR 0.8661——**G0 默认必须是 hybrid**。注意扫描是 60 题、主表是 100/200 题，两组数字不可直接相减。

### 3.3 反直觉 / 负结果

**（1）图审推翻 v1 的共鸣更新式：这是本轮最重要的修正。**

读图时 F3(c) 的曲线显示 `cos(s_t, gold)` 从 0.84 掉到 0.60，最初怀疑是画图选参。数值复核（`/root/logs/res_sim2.py`，dim=48、36 键、20 seeds、4 次迭代、q0 与 gold 的 cos=0.754）确认是**更新式本身的数学缺陷**：未归一化聚合时，m=8 个低置信干扰项的 $\sum a_iV_i$ 噪声量级 ~√m，压过 gold 项，状态向干扰项质心漂移。

| 变体 | final cos(s*, gold) |
|---|---|
| 原式（未归一化，m=8） | **0.612**（比 q0 的 0.754 还差 → 负优化） |
| 凸组合归一（÷Σa） | 0.728 |
| 凸组合 + 中心化 | 0.744 |
| 凸组合 + 幂次锐化 p=4, m=3 | **0.795** |
| 凸组合 + p=8（m=2..6） | **0.972 ~ 0.982** |
| p=8，n_keys 加到 1000 | 0.873+（不崩） |

修法即 §2.3 的锐化式。更重要的是**判据的连带修改**：原 E2 只比「R>1 vs R=1」，但若 R=1 本身也在漂移，就会得到「R=4 漂移得少」的假阳性；修正后 E2 的对照强制包含**原始 q0**（阈值 1.5pt），并给每次 recall 记 `cos(s*, q0)` 漂移报警。这条修正同时说明：**图审（修数学）和冒烟（修「哪些组件其实没被考到」）是两件事**。

**（2）真实数据上「用 s 重排候选」有害。** 与合成 loop 里「把 s 作为下一轮 query 特征」不同：LME oracle MRR 0.7041→0.7037→0.6831（R=0/1/4）、LME_s 0.7142→0.6870→0.6337、LoCoMo 0.3788→0.3625→0.3365。v3 只保留 feedback 特征，删掉重排路径。

**（3）J3 的零增益是结构性的，不是 meta 没用。** 1450 items / 80 test 下所有变体（含 no_rules）acc 全部 0.8125。读代码定位到原因：提交阶段 `if node.claim_kind != want_kind: continue` 是硬过滤，`_answer_from` 又按问题里点名的关系硬选 terminal —— kind/rel 两类 meta 与手写规则**结构性冗余**，加成项永远影响不到结果。要让 JEV-Meta 有价值，只能二选一：规则-free 的 loop，或只训规则算不出的标签（极性、utility、injection、is_old、实体规范化）。

**（4）合成标签 1.0 是模板泄漏。** 零样本 EG2-typed-decision 直接当记忆 meta 标签器：kind acc 0.52、evidence AUROC 0.398（比随机差，全说 yes）；36s 后训后 kind/rel 1.000、is_old AUROC 0.975、evidence 0.958。合成流里 kind/rel 直接写在文本里，1.0 只能当乐观上界，真实数据必须换弱标签验证（J6 就是那一步）。

**（5）真实数据的证据标签继续失败（J8）。** 把问题放进 state、做类别平衡的问题条件化证据识别：macro per-question evidence AUROC **0.5523**（pooled 0.5524，n_test 21,628 pairs / 30 题），反而低于纯文本的 0.677；检索 recall@10 在 λ=0/0.05/0.1/0.2 下全为 0.9756，零增益。结论：真实证据标签需要更强的 teacher，问题条件化本身救不了标签质量。

**（6）决策后训练与通用检索不同源（J5b）。** 同一底座两个产物：合成逐跳 top-1 0.217→0.273（+5.6pt，域内受益），但 LME_s flat recall@10 0.960→0.900（−6.0pt，真实检索灾难遗忘）。要单模型必须加 anchor 损失：γ=0.5 不够（−5pt），γ=2.0 把 −6pt 收回到 −2pt（0.940 vs EG2 0.960）且 evidence 反而升到 0.917，γ=4 是平台。注意 γ 表中 LME 数字来自 50/20/10 题不同子集，只在同 run 内可比。

**（7）元实验（n=1）：结构化审计字段没有换来更好的决策。** 同一份 14 步计划，两种 Lead 执行形式（RR-Tree vs 散文）各配 4 名审阅 worker、另加 2 名盲评 judge，预注册 + 随机化顺序：总分 Prose 90.5 vs RR 94.0（+3.5），但预注册判据要求 ≥+5 且成本 ≤1.5×，实测成本比 1.87×（memo 长度）、墙钟 1.62× → 触达 ceiling_rule，结论只能是**无法区分**。缺陷召回 36/36 双方打平、误报 0/0、植入错误识别 4/4 双方打平——任务对两种形式都太容易，RR 买到的是可审计分（20/20 vs 6–11），付出的是 1.87× 成本与内部计数不一致（验收段写 preflight 3 条 FAIL，preflight 小节实际 5 项 FAIL）。

## 4. 结论与判定

**判定：部分完成。** 依据是预注册判据的结算：E1 在 ≥3.4k items 成立（+7.5pt）但 <1k 反向，未达「砍树」条件；E2 多步共鸣判伪（三个规模零增量，命中 kill 判据）；E3 测法无效、需重做；E4/E5/E6/E7 未跑；J 系列成立，但 J1–J5 是合成流、J6/J8 虽有真实数据却只有 30–32 题（n=80/62/50/32/30，单 seed、无 CI），端到端答案正确率从未测。

| kill criterion | 阈值 | 实测 | 结算 |
|---|---|---|---|
| E1 树 vs 平铺 | 增益 <2pt ⇒ 砍树 | 3.4k +7.5pt、9.4k +37.5pt、458 −1.3pt | 未判死 |
| E2 多步共鸣 | 相对 max(R=1, q0) <1.5pt ⇒ 判伪 | 0 增量（三规模） | **判伪** |
| E3 量化 | 4-bit 与 16-bit 差 >0.5pt ⇒ 改 8-bit | 非单调，测法无效 | 不可判 |
| E4 门错误累积 | 注入 10% 错误掉 >10pt ⇒ 上 verifier | 未跑 | 未结算 |
| E5 后训练 | 提升 <2pt ⇒ 判负 | 未跑（只有 J 系列标签器） | 未结算 |
| E6 三态 | fail-open 不如弃权 ⇒ 改协议 | 未跑 | 未结算 |
| E7 oracle-free gap | gap <3pt ⇒ 收工 | 未跑 | 未结算 |

**可写（支持的结论）**

1. 树的收益是**规模相关**的：458 items 时平铺略好（0.800 vs 0.7875），3,265 items 时树 +7.5pt、打分节点 1/4.2，9,397 items 时 +37.5pt、节点差 10.7×。只说「≥3.4k 区间占优」，不说「树普遍更好」。
2. `score = cos(内容) + 0.02·meta_match` 这种「内容主导 + 标签轻量门控」在逐跳寻址上有效：oracle meta +28.8pt、预测 meta +26.5pt，且预测标签能复现 oracle（λ=0.05 时数值完全相同）。
3. 冻结 4B 的零生成读出可以产出 meta 标签（kind/rel 1.0、is_old 0.9495），36s 后训的 EG2 标签器同样可用（kind/rel 1.0、is_old AUROC 0.954、evidence 0.965）——「JEV 当标签器」这一步在合成上成立。
4. 时间/recency 类标签**不能靠读文本**：J6 的 recency acc 0.3308（≈chance 0.333），J7 把写入时 timestamp/position 放进 state 后升到 0.9751。

**不可写（诚实边界）**

1. 不能说「共鸣有效」：多步迭代在三个规模上零增量（判伪）；单步 feedback 只有 +1.2~3.7pt 且 9.4k 上反向，无 CI、无多 seed，不足以下正结论。
2. 不能说「树普遍优于平铺」：<1k items 反向；真实数据上默认 b8/c16 丢 5.9~7.4pt 召回，收益要靠加宽或换语义树才出现。
3. 不能说「JEV-Meta 在真实场景可用」：所有 1.0 来自模板泄漏的合成流；真实数据上 evidence AUROC 0.677，检索只 +0.7pt 而 oracle 能 +7.7pt，瓶颈是标签质量。
4. 不能说「端到端答案提升」：这条线一次都没测答案正确率，所有增益都是检索/寻址代理指标。
5. 不能说「后训练免费」：J5b 的 −6.0pt 证明决策与嵌入同源不是免费的，γ=2 只把损失压到 −2pt。

**对后续决策的含义**：不做端到端答案之前，不再往树/共鸣/门上加新组件；下一阶段三个口子——规则-free loop（公平测「学习替代规则」）、更强 teacher（JEV-9B 需 vLLM adapter，未接入）、写入端结构化元数据（J7 已证最便宜）。

## 5. 踩坑与修正

| 现象 | 根因 | 解法 |
|---|---|---|
| mock 编码器上树 +25pt（0.912 vs 0.662），真实 EG2 的 458 items 上树反而 −1.3pt | hash mock 对实体 token 过于敏感，放大结构差异 | mock 只用于验证管线，任何结构结论必须换真实编码器重跑 |
| 无卡模式加载 EmbeddingGemma2 无 traceback 静默死亡，日志停在 `Loading weights: 0%` | cgroup 内存上限 2GB，1 CPU 核 | 模型冒烟必须切 GPU；无卡模式只用来下载 |
| 合成流 ≥2.8k items 时树与平铺同时跌到 0.163 | 模板相近 claim 在 top-32 里互相挤出（候选排序容量），不是树的问题 | 规模结论只认真实数据；合成流不做规模实验 |
| 默认树 b8/c16 在 LME_s 丢 6pt 召回 | 时间桶先切，top-8 桶只覆盖 20% 池 | 加宽路由或改语义树；G0 默认 hybrid RRF |
| J3 所有变体 acc 完全相同，连规则消融都测不出差异 | 提交阶段 kind 硬过滤 + 关系硬选，meta 结构性冗余 | 要么规则-free loop，要么只训规则算不出的标签 |
| E3 量化 2-bit 反而更好 | 量化只作用在排序键，粗量化制造 ties 改变了提交顺序 | 量化分数必须作为状态/判定输入再评 |
| 图里 `a_i` 来自 JEV 门，门却画在共鸣之后 | 架构循环依赖（v1 图自相矛盾） | 改两遍门 G1a→共鸣→G1b→G2；G2 只在叶层 |
| 数据规模曲线跨 run 不可比（题目集随 items 变化） | 每次 run 重新生成 queries | 受控实验固定问题、只追加干扰项；规模只报同题集 |
